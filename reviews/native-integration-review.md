# Native integration review

Read-only review of `src/app.rs`, `src/presentation.rs`, and `src/session.rs` after the Task 6 viewport GPU tests. Findings below are source-derived, not additional desktop observations. Line references describe the reviewed snapshot and can move while the parent applies fixes.

## Findings to fix

1. **Accepted geometry and edited import settings can disagree after failure (high).** `app.rs:531–578` preserves the previous model after a failed reimport but clears `importing`; `snapshot()` at 343 then combines that model with the current `scene.import`. Example: import ordinary STL, enable stepped envelope on an unsupported/open source, wait for failure, then export. The old smooth mesh is exported while `model_scene()` disables Layer Appearance because the edited setting still says stepped. Failed G-code height/filament reinterpretations similarly leave old deposition geometry paired with new physical metadata. Keep the accepted import settings with the model/result and either restore those on failure or block exports until edited settings successfully produce geometry. Test failure after a prior successful import, then assert mesh/settings coherence in export and project serialization.

2. **Editing settings during the first import does not invalidate its result (high).** `app.rs:852–860` handles import-setting changes only when `self.model` exists. Start a slow first import and change units/build rotation or G-code options before completion: the active old-settings result still passes the generation gate. Track the requested source independently of the accepted model and requeue the latest request even before the first success. The same accepted-settings snapshot suggested above makes the invariant testable. Existing bounded one-active/one-pending replacement logic is otherwise sound; debounce edits already advance the gate when a model exists.

3. **Build-up animation repeatedly scans the full CPU mesh (high for the performance target).** `app.rs:908` and `1164` call `mesh.bounds()` each frame while the build-up controls are open/playing. `Mesh::bounds()` traverses every position and every triangle index. Playing therefore adds two complete CPU mesh validation scans per frame, outside the previously measured persistent GPU render cost. Store bounds/build height once with the accepted model and reuse it. A regression check should establish that animation/control updates do not invoke geometry validation or allocation; then measure actual desktop animation with the million-triangle fixture.

4. **The printed-height control does not use adaptive layer boundaries (medium).** `viewport_settings()` at 294–302 passes raw height for G-code because groups exist, so the slider slices through a bead instead of advancing complete deposited layers. STL uses uniform snapping even when an explicit adaptive schedule produced the stepped solid. Select the greatest actual accepted layer top at or below requested height from G-code groups or the accepted explicit/clipped STL schedule; pass the resulting height with `buildup_complete_layers=false`. If continuous clipping is intended, label it as clipping and expose an explicit complete-layer option. Test boundaries such as `[0, .2, .5, .6]` at requested height `.45`, including the final clipped top.

5. **Decoded output events can become stale after the worker finishes (medium).** `app.rs:615–634` gates successful preview images by scene revision, but stale preview decoding failures still replace the current error. Nonpreview images carry no job ID and always replace `self.output`. A slow old GIF decode can finish after a later PNG decode and overwrite it while `last_output` points at the newer file. Carry job ID through `Message::Image` and discard both success and error for superseded jobs; preserve the scene revision gate for previews. Also retain a decoding/in-flight state for automatic previews: `busy` is cleared before decode, and until `preview_revision` is set the auto-preview condition can submit another render of the same revision. Test deliberately reversed completion order and delayed decode.

6. **A prior G-code palette can freeze the next STL's native color (medium).** The scene retains `color_mode` when opening another model. At `app.rs:1170–1189`, a nonuniform mode allocates a full face-color array even when the new model has no groups, while the invalidation signature contains only `color_mode` and `tool_colors`. For an STL opened after tool-colored G-code, the UI hides Color mapping but native rendering continues using the baked face colors; subsequent base-color changes do not rebuild them. Treat models without groups as uniform and send an empty color array. Test colored G-code -> STL -> edit base color, comparing native and render scene intent. Palette changes currently rebuild all vertex buffers synchronously on each color-widget edit; consider debouncing that expensive path for dense geometry after correctness is fixed.

## Secondary observations

- Renderer selection/transparent background are outside the `scene` revision comparison, so changing them does not invalidate an existing auto-preview. Include render-affecting preview settings in its revision key or state clearly that they apply only to subsequent manual/export jobs.
- `RenderService::submit()` clears a shared cancellation flag before `try_send()`. Current Studio busy gating prevents overlapping submission, but the public service can undo cancellation even when a new submission fails because its queue is full. Per-task cancellation or explicit rejection of concurrent submissions would make the service invariant self-contained.
- Job records are marked running before `snapshot()`/submission succeeds (`app.rs:416–450`), so metadata-budget validation errors can leave a never-started job recorded as running. Validate the immutable snapshot first or mark the record failed on this path.
- `restore_project()` restores explicit adaptive boundaries but does not refresh `adaptive_text`, which can display/edit stale text from the previous project.

## Reviewed behavior that is consistent

- `presentation.rs` reproduces joined-path segmentation using the same endpoint/tool/feature/layer criteria as the geometry builder. Side-face ranges and cap inclusion match the Python smoothing contract. Independent circular/stadium face counts match the legacy builder.
- `model_scene()` explicitly disables shader layer appearance for a successfully built stepped envelope; it does not double-apply the layer effect in the normal success path.
- Render task scene values and mesh `Arc`s are immutable snapshots. Worker events are filtered by active job ID before updating progress or completion. The remaining stale window is asynchronous image decoding after completion.
- Default native clipping acts in original build coordinates, GPU cutaway remains explicitly uncapped in the UI, and Ghost/X-ray use actual triangles with preserved voids. These GPU contracts were verified separately in `reviews/viewport-implementation.md`.
- Source size and metadata budgets are explicit; source changes during import are checked. The slicer remains labeled experimental and does not imply general toolpath/print prediction.

No parent source was edited and no extra Cargo/test run was started during this review.
