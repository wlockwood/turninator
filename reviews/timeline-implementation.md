# Camera timeline and combined build-up implementation

This extends the updated TODO's view transitions and combined model actions. The older explicit rejection of build-up plus sections is superseded by actual per-frame geometry processing; existing fixed turntable and standalone build-up defaults remain available.

## Shared timeline contract

`animation::{Timeline,CameraKeyframe,Transition,Easing,AnimationSample}` is serializable through the timeline/key types and uses the existing physical `OrbitCamera`. Timeline fields are `duration_seconds`, `looping`, `keyframes`, `turntable` and `buildup`. Each key stores `time_seconds`, `camera`, outgoing `transition: Orbit|Spiral`, outgoing `easing: Linear|SmoothStep` and `spiral_turns`. Spiral turns must be whole values from -100 through 100: fractional extra turns would cause a camera jump at the next key. Plain orbit follows the shortest azimuth route; spiral adds the requested full turns while pitch, target and framing approach the next key. Target motion creates pans. Positive distance/span interpolate logarithmically; pitch and field of view interpolate linearly after easing.

Validation bounds duration to 0.05–500 s and keys to 1–256; the first key is at zero, times strictly increase within duration, and cameras are finite and use a single projection. A loop may leave a closing interval from its last key back to the first, or explicitly end with the first camera. Nonmatching explicit loop endpoints are rejected. This prevents an unannounced camera snap; a cumulative build intentionally resets between loops.

`sample(time)`, `sample_frame(index)` and `worker_frames()` are shared by the native UI/export integration. Export uses 20 fps, rounding duration to the nearest 50 ms and at most 10,000 frames. Nonlooping clips include the final camera pose; loops omit the duplicated endpoint. Build-up's final exported frame always contains all deposited layers. `AnimationSample` carries the camera, optional object turntable angle, and optional cumulative build fraction. These represent whole deposited layers, not toolhead position, filament flow rate or elapsed printer time.

`ExportRequest.timeline` is optional and defaults to absent. Camera timelines apply to GIF/MP4 animation exports; stills and four-view sheets remain static outputs. Effective frame count is derived from the timeline, and its complete settings enter the render fingerprint. An independent encoding recipe permits changing GIF/MP4 encoding without invalidating verified render frames.

Static snapshots use `ExportRequest.build_stage: Option<BuildStage>` with `BuildStage { visible_layers: u32 }`. Zero means an empty build; positive values select that many complete deposited layers, including noncontiguous source layer IDs. Counts exceeding the actual source layer count are rejected. This works for PNG, canonical four-view sheets, sections and fixed-stage animations. It cannot simultaneously select a progressive build schedule. Full-source framing remains unchanged. `start_angle_degrees` defaults to zero, accepts finite values bounded to ±1e9, and preserves the native sampled object angle for still/section snapshots; explicit timelines and canonical sheets normalize it to zero. Both fields enter the rendering fingerprint.

## Worker, section and material behavior

The native exporter writes one bounded `frame-states.json` sidecar and passes that exact path to both full and section panels. This avoids expanding the 1 MiB request-line protocol for long clips. The worker limits the sidecar to 8 MiB, validates exact frame count, camera vectors/projection, finite angle and monotone 0–1 build fractions, then hashes parsed state data into the render manifest. Explicit timeline cameras bypass automatic turntable fit: authored target/distance/span are respected. Lighting and full-source framing remain stable as layers appear. Camera-dependent physical-layer shading filters are refreshed for animated camera position/FOV, without changing physical layer pitch.

Long completion events also remain below the protocol limit: full results and per-frame section measurements are retained in `render-result.json` and `frame-analysis.json`, while an oversized stdout event returns a bounded summary with the result path. Native section export reads the bounded per-frame sidecar when needed. A regression covers a 10,000-frame completion with 50,000 source layers.

For a build-up section, each frame starts from the complete, material-assigned source mesh, removes all faces belonging to future layers, and only then applies the existing closed-solid Boolean cut or explicit uncapped open-mesh handling. This retains real bead geometry and voids. No whole-part envelope is filled. The section plane stays in build space and follows presentation/object rotation. The full panel uses the same visibility schedule and exact camera states. Every frame's section statistics derive from that frame's revealed mesh; `frame-analysis.json` retains visible layer/source-face count, cross-section area, original visible volume and remaining cut volume. Overlap/algebraic-volume and unfused resin-interface warnings remain explicit.

## Verification

- Four pure timeline tests cover left/right-to-top orbit, panning/zoom, smooth spiral turns, loop closure without endpoint duplication, complete final build frame, serialization, out-of-range/nonfinite inputs, projection discontinuities and invalid fractional turns. The initial test run failed for the missing timeline API, then passed after implementation.
- Pure Python tests initially failed for missing timeline validation/layer-selection helpers, then passed. Full discovery currently passes 42 tests, including the existing renderer/encoder integrity checks. Four timeline, five export and five project-timeline tests pass; strict all-target Clippy passes.
- `cargo test --offline --test timeline_runtime -- --ignored --nocapture --test-threads=1` passes both actual Blender 4.5.2 runtime tests in 31.39 s. The Cycles/OptiX test renders four frames of two separate paths across four layers, resin/tool colors/dark studio, a spiral-to-top with pan, capped X section and paired full/section layout. The GIF decodes as 256×128, four frames, 200 ms, with the standard final delay and loop checks. Full and section manifests have identical camera-state hashes.
- Visible source volume increases from 7.061468 mm³ to four times that value, and every frame retains exactly half after the X cut within numerical tolerance. First-layer cut area is 0.882683 mm² for the two beads; the 6 mm gap is not replaced by a filled envelope. A second AV1 export reuses all section PNG timestamps unchanged. Separate transparent Cycles PNGs combine the same timeline, resin and section while retaining both transparent background and visible geometry pixels.
- First/final paired images were inspected. The final top view intentionally hides the height behind the topmost layer; the per-frame mesh measurements establish complete geometry growth. This small compatibility fixture is not a performance claim for dense print Boolean operations.
- Artifacts: `artifacts/timeline-section-proof/{paired-resin.gif,paired-resin-av1.mp4,result.json}`, retained full/section frames and per-frame analysis, and transparent PNGs. Existing broad geometry/rendering evidence remains in `native-render-implementation.md`.
- The second runtime test exports a selected first layer to a 256×256 PNG and four-view sheet, verifies that revealing all four layers increases occupied pixels without reframing, checks the retained 37.5° object angle, and renders zero/one-layer capped sections. The first-layer still has 4,219 pixels with alpha above 128; the zero-layer section has none. The sheet and partial section were visually inspected. Evidence is in `artifacts/static-build-stage-proof/result.json` and its PNGs.
- A separate persistent-worker EEVEE probe rendered a supplied original model with physical 0.2 mm layer pitch, 0.3 mm first layer, moving camera/FOV and transparency, followed by the four-frame resin/section timeline. It passed in 16.11 s; alpha, distinct camera frames and the resulting images were checked. This exercises camera-dependent layer filtering and the combined features in EEVEE as well as Cycles. Evidence is in `artifacts/timeline-camera-proof/result.json`.
