# Blender worker implementation evidence

Owned files: `renderer/scene.py`, `renderer/worker.py`, `tests/test_renderer.py`.

The worker now accepts protocol-1 `probe`, `render`, and `shutdown` requests. All Blender work occurs in the main-thread input loop. Every request exception emits a typed error and leaves the worker available for following requests. Prefixed events retain request ID and scene revision. Invalid envelopes are sanitized for error reporting; lines have a 1 MiB bound. The controller remains responsible for process-tree ownership, deadlines, cancellation and stream draining.

The mesh reader checks magic/version, nonempty counts, budgets, exact file size, finite positions, index ranges and degenerate float32 triangles. Limits match Rust at two million vertices and four million triangles; these bound input, not guaranteed GPU fit. Scene JSON is limited to 1 MiB, requires absolute paths, and validates schema, physical layer height, color, roughness, rotation and warning types. Tests import these helpers without Blender.

Scene construction converts millimeters to meters exactly once, bakes XYZ presentation rotation, centers the resulting geometry around the spin axis and raises its minimum Z to the studio floor. A conservative sphere around the full rotation cylinder fits a fixed 70 mm camera with 10% margin. Lights, camera and exposure remain fixed throughout the sequence. Live initial output exposed excessive area-light power; it has been reduced by 100x pending the root agent's next visual check. Tagged `independent_stadium_v1` bead meshes validate side/side/start-cap/end-cap triangle quartets, then use smooth sides and flat caps. Untagged beads remain flat, avoiding guessed layout or cap-normal pollution.

Cycles explicitly selects available OPTIX devices and disables CPU devices. Missing OPTIX produces an error rather than CPU substitution. EEVEE uses `BLENDER_EEVEE_NEXT`. The probe reports Blender version/build hash and device identities. Actual runtime availability and appearance are established by the root agent's integration proof, not these pure tests.

Frames render to `.partial.png`, load back through Blender's PNG decoder, validate signature/dimensions and accessible pixels, then promote to `still.png` or `frame_0000.png` etc. Existing final frames are refused by default. An explicit `reuse_verified_frames: true` requires an exact matching worker-written `render-manifest.json` covering scene, geometry hash, script hashes, Blender build and render recipe. Matching decoded frames emit `reused: true`; corrupt or missing frames render again. Mismatched/absent manifests reject reuse. Verified preceding frames survive later failures. A complete event includes frame paths/timings, preparation/total time, engine/samples/size, geometry hash/counts, bounds, devices and source warnings. Meshes are rebuilt per request; cross-request mesh caching is deferred.

Test evidence: first `python -m unittest discover -s tests -p test_renderer.py -v` failed because `renderer/scene.py` did not exist. After implementation the seven initial checks passed. Two additional protocol regression checks exercise malformed request recovery and render-exception recovery without Blender. Runtime rendering, full GIF timing/playback, Windows process cancellation and final 4K artifact review belong to the integration controller and are recorded separately.

Additional regression evidence: four new cap-layout/power/reuse tests failed before implementation, then passed. A degenerate-triangle check and expanded appearance-validation test failed before their implementation, then passed. Current renderer suite has 14 passing tests. The complete Python suite and real runtime checks remain integration evidence.

Optional original-mesh `layer_appearance: true` now builds a physical groove shader. It accepts `first_layer_height_mm` (default selected height) and `groove_depth_mm` (default 5% of pitch, limited to 25% of the smaller first/regular height). A saved build-Z vertex attribute preserves phase across baked presentation rotation; true geometry normals transformed back to build orientation mask horizontal caps. Bead meshes cannot enable this second groove effect. The shader's exact Blender-node API and real visual result require the root agent's live original-model render. Subpixel adaptive filtering is not implemented; fine distant grooves may alias. It preserves source silhouette and is not stepped geometry.

Known limits: independently capped segment joins can still create corner/end overlap artifacts; no union is attempted. Pure input/worker tests do not prove GPU rendering or visual realism. No arbitrary camera settings, multiple materials, transparent-resin physics, UI job resume or mesh cache is claimed. Transparent backgrounds remove the floor; material transmission is unchanged.
