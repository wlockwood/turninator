# Native face picking and settle orientation

Implemented the new `todo.md` face-settle item's geometry/native layer. Root owns import/UI wiring, desktop smoke, project integration and commits. No package files were changed for this slice.

## Contract

- `model::orientation::settled_display_rotation(old_euler, build_normal) -> Result<[f64;3]>` composes a shortest world-space rotation aligning the selected winding normal with -Z, then returns XYZ Euler degrees. It changes presentation orientation, preserving build-space geometry and physical layer coordinates. The pure helper is also usable for a separately selected physical STL build-orientation feature, when supplied with that orientation's source normal. It handles antiparallel normals deterministically and extracts pitch with `atan2` to avoid losing precision at gimbal poles.
- `rotation_matrix([f64;3]) -> Result<[[f64;3];3]>` uses the same Euler XYZ convention. Finite nonzero normals are normalized using a scaled norm; invalid angles and zero/nonfinite normals fail explicitly.
- `viewport::PickingMesh::new(&Mesh) -> Result<Self>` constructs a bounded median-split BVH using GPU-representable f32 positions, original triangle order, and leaves of at most eight faces. Construct this during background import and retain it in `Arc<PickingMesh>`; no BVH rebuild occurs on click. Existing mesh budgets (2M vertices, 4M triangles), finite-coordinate checks and f32-degenerate-face rejection apply.
- `PickingMesh::set_triangle_layer_tops(&[f32])` consumes original-triangle-order metadata; empty input clears it. Build this metadata before sharing the picker. Validation and semantics match GPU whole-layer visibility, including exclusion of future beads' bottom caps.
- `FaceHit {triangle_index, point_mm, normal_mm}` returns original mesh/build coordinates. `normal_mm` is a unit winding normal, never flipped toward the camera. For a consistently wound solid, this is its outward normal. The helper does not repair inconsistent winding or simulate physical stability/contact on concave models.
- `PickingMesh::pick(camera, settings, ndc, aspect)` supports perspective/orthographic camera rays, pan/zoom, near/far clipping, display Euler rotation, actual rotated-vertex XY centering/minZ flooring and subsequent turntable spin. It rejects invalid/outside rays. Section and build-up discarded surfaces do not occlude retained surfaces. Ghost/X-ray pick the nearest retained actual surface.
- `Viewport::pick_at(picker, camera, settings, response.rect, pointer)` is the UI integration entry point. It reuses the viewport's cached center and physical texture aspect, avoiding another vertex scan on click. The standalone picker caches centering by display pose. `picking::pointer_coordinates` maps logical screen coordinates to NDC, including screen-Y inversion and outside rejection. `Viewport::show` now uses click-and-drag sense so ordinary clicks can be selected while drag orbit/pan remain available.

The GPU and picker share `ViewportSettings::effective_buildup_height`; the uniform/first-layer snapping behavior cannot silently diverge between drawing and selection.

## Tests and evidence

1. Wrote the initial five integration tests before implementation. `cargo test --offline --test picking` failed with missing orientation/PickingMesh APIs. After implementation, four passed and the settle test exposed a nominal 90-degree orientation tilting by `1.49e-8` radians because `asin` amplified rounded unit-sine error. Replaced Euler pitch extraction with `atan2` of the actual matrix components; all five passed.
2. Added arbitrary XYZ/spin/floor and pointer-axis checks. Final `cargo test --offline --test picking`: **7/7 passed**. Coverage includes both camera types, nearest-hit occlusion, shared triangle edges, camera pan, arbitrary pose and spin, clipping/whole-layer visibility, invalid metadata preserving old state, exact opposite normals, gimbal cases, unchanged already-down orientation, invalid rays, nonfinite meshes and the 4M-face budget.
3. `cargo test --offline --lib bvh_`: **1/1 passed**. A spatial query against 20,000 triangles finds the correct nearest source face while testing fewer than 32 triangles, confirming bounded spatial traversal rather than a full face scan.
4. Added actual GPU `gpu_click_pick_and_settle_match_rendered_surface`. It renders differently colored source faces and compares clicked triangle identity to the actual pixel's dominant color, across perspective/orthographic and three poses including gimbal. It then settles that selected face, verifies its normal is down and the selected convex-face vertices are on the displayed floor, and renders physical layer appearance in the new pose.
5. `cargo test --offline --lib gpu_ -- --ignored --nocapture`: **4/4 actual GPU tests passed**, 1.29s total, RTX 4070 Ti/Vulkan/595.79; zero GPU validation errors. Existing layer, section, OIT, caps, resize and unload checks still pass.
6. `cargo clippy --offline --lib --test picking -- -D warnings`: passed. Owned Rust files are rustfmt formatted. `cargo test --offline --all-targets`: **76 passed**, 14 explicitly ignored GPU/proof workloads. The four native GPU correctness workloads were separately executed successfully above.

Source geometry is not rewritten by a presentation settle. The existing viewport and Blender transform contract places the actual transformed minimum Z on the floor. For a convex selected support face this places that face on the floor; for an interior/concave face, another part can extend farther down. No stable-contact or collision simulation is claimed. Desktop pointer-mode activation and project persistence require root's UI integration proof; offscreen GPU assertions do not replace that proof.
